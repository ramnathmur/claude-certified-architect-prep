How the mock exam system works

What one exam is built from, how to run it, and what changes between one exam and the next. Covers the prep with quiz mock-exam generator specifically — not the rest of the prep project.

What you're taking

Built on the real exam's blueprint — deliberately not a copy of it

Every mock exam is grounded in the official Anthropic Exam Guide for Claude Certified Architect — Foundations: 60 questions, 120 minutes, 5 weighted domains, a scaled score of 100–1,000 with a pass line of 720, and 4 scenarios drawn from a bank of 6 per sitting. The mock exams here follow that same structure.

But this tool is built to teach, not to simulate exam pressure. That's a deliberate choice, not an oversight — so a few things work differently on purpose:

Real examThis practice tool
No feedback until the whole exam is overFull explanation shown immediately after every single question
Hard 120-minute clockA silent elapsed-time clock — for your own pacing, no countdown, no cutoff
Must answer every question before advancingYou can submit with questions unanswered, or leave and come back — your answers and timing are saved automatically as you go

Realism lives in the question style, difficulty, topic coverage, and structure — not in withholding the answer.

Structure

What one mock exam contains

A full mock exam is 60 questions in 4 scenario blocks of about 15. Each block follows one evolving storyline — the same fictional company and system, with the situation developing across its 15 questions — rather than 15 unrelated vignettes. The 4 blocks are drawn at random each time from an official bank of 6 named scenarios, so no two exams are guaranteed to look alike, and every scenario surfaces sooner or later.

1 · Customer Support Resolution Agent

MCP tools for lookups, refunds, escalation

2 · Code Generation with Claude Code

Slash commands, CLAUDE.md, plan mode

3 · Multi-Agent Research System

Coordinator + subagents, cited reports

4 · Developer Productivity with Claude

Built-in tools, codebase exploration

5 · Claude Code for CI/CD

Automated review, test generation

6 · Structured Data Extraction

JSON schemas, validation, accuracy

Questions are weighted by domain, and that weighting holds across the whole 60-question exam — not per block:

DomainWeightQuestions / 60
D1 — Agentic Architecture & Orchestration27%16
D2 — Tool Design & MCP Integration18%11
D3 — Claude Code Configuration & Workflows20%12
D4 — Prompt Engineering & Structured Output20%12
D5 — Context Management & Reliability15%9

Each question opens with a concrete Situation — a log line, a metric, a user's message — never an abstract description, and offers exactly 4 options: one correct, three built from misconceptions the exam actually tests, not arbitrary wrong answers. There's also a shorter 30-question Drill format (standalone questions, no shared storyline) for a quicker check-in — the full 60-question format is the default because it's the closer match to the real thing.

The core mechanic

Every option gets explained — not just the one you pick

This is the tool's central design choice: whichever option you choose, right or wrong, you get the reasoning for all four — where the correct answer comes from and exactly why each of the three distractors fails. Here's a real question from Mock Test 2, shown both ways:

D4 · Prompt Engineering & Structured Output
Aria still misroutes borderline messages like "I need help with my recent purchase" between get_customer and lookup_order. An engineer plans to add few-shot examples to the system prompt to fix it and asks how to choose them. Which approach most effectively improves selection?
A Add 10–15 examples of clear, unambiguous single-tool requests so Aria sees many correct mappings for each tool.
B Add 4–6 examples targeted at exactly the ambiguous cases where Aria misroutes, each with a rationale for why one tool was chosen over the other.
C Add one worked example per tool covering its most common request, keeping the prompt short.
D Replace the examples idea with a longer, more emphatic instruction listing every rule for choosing between the tools.
If you pick B — correct
Why B is rightFew-shot examples should target the specific ambiguous cases where the model gets it wrong — 4–6 examples aimed at the edge cases, each with a rationale — not a pile of easy, unambiguous ones.
Source: Domain-4_v2 §4.1
Why A, C, D are still wrongShown too — so you see the traps even on a question you got right.
If you pick A — not quite
Why A is wrongTen to fifteen unambiguous examples don't address the ambiguous edge cases that actually cause misrouting; the exam explicitly rejects flooding the prompt with clear-cut examples.
Source: Domain-4_v2 §4.1
Why C and D are also wrongShown next, same depth.
Then: the correct answer, BWith its full "why it's right" text.

Every rationale on screen names the exact source it comes from (like Domain-4_v2 §4.1 above), so you always know precisely where to go read more.

Running it

How to generate or continue an exam

1
Open a Claude Code session in the prep with quiz folder.The system reads and writes several files (logs, dedup lists) using paths relative to this folder — starting elsewhere won't resolve them.
2
Type /cca-exam.It prints a short status block — how many exams exist, how many are scored, your last result, any confirmed weak spot — then asks whether you have a result to report or want the next exam.
3
Generating a new exam?Confirm the format — Full (60 questions, 4 scenario blocks) is the default and the closer match to the real exam, or Drill (30 questions) for a quicker session. The exam is written as one self-contained HTML file into prep with quiz/mock-exams/ — open it in any browser, no install, works offline.
4
Finished an exam?On the results screen, click "Copy results JSON." That's the one thing to do right after taking an exam.
5
Report the score.Next time you run /cca-exam, paste that JSON in when it asks. This is what lets the system credit you accurately, question by question and domain by domain — typing a bare total like "I got 44 right" still works, but only as a rough fallback, since it can't tell which questions you missed.
Continuity

How your last score shapes the next exam

After every exam you score, the system writes itself a short note — 2–3 specific things you got wrong, your weakest domain, and one line of intent for the next paper. The next exam reads that note and quietly leans its question choices toward what you missed, without ever dropping the other domains or changing how many questions each domain gets. Every exam stays a full, representative paper; it just leans toward your gaps.

If the same domain comes out weakest two exams in a row, that counts as a confirmed weakness, and the next exam gives that domain 4 extra questions (pulled evenly from the two lowest-weighted domains). One rough exam won't trigger this yet — but it will already start shaping which sections get tested within that domain, from the very next exam.

Two separate guarantees keep every exam fresh: no stem is ever repeated across your own mock exams, and none is ever repeated or closely mirrored from the separate 76-question official practice test you'll be sitting on your own — so the two always give you independent readings of where you stand.
