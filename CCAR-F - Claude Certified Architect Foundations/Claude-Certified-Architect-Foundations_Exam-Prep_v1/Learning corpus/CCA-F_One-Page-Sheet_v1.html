CCA-F — one page

60 q · 120 min · 4 of 6 scenarios · pass 720 / 1000

The five domains

D1Agentic Architecture & Orchestration27%Loop control, coordinator delegation, decomposition, handoff, sessions
D2Tool Design & MCP Integration18%Descriptions, structured errors, tool_choice, MCP, built-ins
D3Claude Code Configuration & Workflows20%CLAUDE.md, rules, skills, plan mode, CI
D4Prompt Engineering & Structured Output20%Few-shot, schemas, validation, retries, batch strategy
D5Context Management & Reliability15%Statelessness, compression, provenance, escalation signals, confidence calibration

Hard rules

  • Loop terminates on stop_reason — never on text content or an iteration count.
  • Coordinator spawns subagents because "Task" is in allowedTools — never because the prompt tells it to delegate.
  • Correct subagent output plus missing topics means the coordinator decomposed too narrowly - never blame subagent quality.
  • Plan mode for wide scope, many files, or several viable approaches — never start direct and switch when it gets hard.
  • Misrouting is fixed by rewriting tool names and descriptions — never by adding a classifier, router, or bigger model.
  • Each agent carries 4-5 role-scoped tools — never the full catalogue "for flexibility".
  • Schema-valid JSON is guaranteed by tool_use plus tool_choice — never by asking the prompt for valid JSON.
  • Force a named tool only on the mandatory first step, then relax to auto - never leave tool_choice forced every turn.
  • Fields that may be absent are nullable and null is a valid answer — never required "for data quality", never a raised retry limit; absent information stays absent.
  • Few-shot targets the 4-6 ambiguous cases — never 10-15 clear ones, never more prose when the instructions are already failing.
  • Policy denial returns retriable:false plus a customer-friendly explanation - never a generic "operation failed" the agent retries.
  • Review runs in a second instance with no access to the generator's reasoning - never a second pass in the same conversation.
  • Prefer prompting the agent to bundle related tool calls into one turn over a composite tool that hides the composition.
  • Amounts, IDs and dates live in a case-facts block outside the summarized history - never inside what the summarizer compresses.
  • Long inputs lose the middle: key findings first, section headings throughout, upstream agents returning structured facts rather than raw text.
  • CLAUDE.md levels concatenate root-down and accumulate — never assume a lower level overrides a higher one.
  • context: fork isolates a verbose skill in a subagent so its output never pollutes the main session.
  • CI runs claude -p with --output-format json and --json-schema; --batch and CLAUDE_HEADLESS do not exist.
  • Anything a human or pipeline blocks on stays synchronous; batch allows tools and multi-turn history but cannot pause mid-request for a tool_result.

Easy to confuse

  • Grep vs Glob — Grep searches inside file contents, Glob matches file names and paths.
  • Edit vs Read+Write — Edit needs a unique anchor; when non-unique, fall back to Read+Write, never a shorter anchor or sed.
  • tool_choice "any" vs a named tool — "any" guarantees some tool call, named guarantees that specific tool, auto guarantees nothing.
  • Syntax vs semantic errors — schemas eliminate malformed JSON entirely and do nothing about totals that do not sum.
  • Empty result vs access failure — zero matches is a success with isError false; a timeout or dead connection is isError true.
  • .claude/rules/ vs CLAUDE.md vs Skills — glob-path-scoped, always loaded, invoked on demand for a workflow.
  • Fixed pipeline vs dynamic adaptive decomposition — predictable repeatable template vs scope discovered step by step.
  • --resume vs fork_session vs fresh session with injected summary — continue, branch to compare two approaches, restart when tool results are stale.
  • Interacting vs independent issues — interacting fixes go in one message, independent ones iterate sequentially.
  • Behavioral drift vs context overflow — degradation at 2,500 tokens and turn 7 is accumulated assistant turns diluting the system prompt, not window pressure.

Escalation & enforcement

  • Escalate on structural signals: policy silent or ambiguous, repeated failures, no progress after reasonable attempts, high-stakes ambiguity, financial threshold breach.
  • Never escalate on sentiment analysis or the model's own self-rated confidence - mood and uncalibrated self-assessment do not track case complexity.
  • Calibrated confidence is different: field-level scores tuned on a labeled validation set route low-confidence extractions to review, with stratified sampling - a 97% aggregate hides 40% failure on a rare document type.
  • Explicit request for a manager escalates immediately, with no solve-it-first attempt; first expression of anger is not that request - acknowledge, offer a resolution, escalate when reiterated.
  • Several matching customer records means ask for another identifier — never take the most recent or the first result.
  • Handoff payload, because the human never sees the transcript: customer ID, issue summary, order ID, root cause, amount, actions already taken, recommended action, escalation reason.
  • Subagent errors escalate with structured context — failure type, what was attempted, partial results, alternatives - never a bare failure flag, never silent success, never kill the whole workflow.
  • Hard rules live in code: PreToolUse hooks for thresholds and bulk operations, programmatic preconditions for sequencing, two-tool token binding for mandatory preview. Prompts guide; hooks enforce.

Sitting the paper

  • 60 questions, 120 minutes, in four blocks of roughly 15 around 4 of 6 official scenarios drawn at random.
  • Scaled 100-1000, pass 720 — about 42 of 60 raw on the approximation formula; real scaling is psychometric. No partial credit; per-domain percentages informational.
  • No wrong-answer penalty: never leave an item blank, guess and move rather than stall.
  • The guide names multiple-response items once, unelaborated — all 12 official samples are single-answer, four options; any such item states how many to select.
  • The qualifier decides it: "most effectively", "most likely root cause", "first step" - several options are true, only one answers the qualifier.
  • Spend the marginal minute on the D1 item — it carries the most scored content of any domain.
  • An option that adds infrastructure — classifier, larger model, extra agent, post-processor - while a description, schema, or hook fix is on the list is almost always the distractor.

Not on the exam

Do not revise: Fine-tuning, auth/billing, OAuth and key rotation, MCP server hosting, Claude's internals, Constitutional AI and RLHF, embeddings and vector DB internals, computer use, vision, streaming, rate limits and cost math, cloud-specific config, benchmarks, prompt-caching internals, tokenization.
