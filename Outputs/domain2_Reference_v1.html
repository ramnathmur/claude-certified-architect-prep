TS 2.1

Tool Interface Design

Tool descriptions ARE the routing mechanism. Misrouting is a description problem until proven otherwise.

Five Components of Production-Grade Tool Description

  1. Primary purpose — one sentence
  2. Input contract — formats, types, constraints
  3. Example queries it handles well — concrete strings
  4. Edge cases and limitations — what it won't do
  5. Explicit boundaries vs. similar tools — "Use this for X. For Y, use `other_tool`."

The Misrouting Fix-Ranking (Memorise Verbatim)

Fix priority for misrouting scenarios
FixRankWhy
Expand tool descriptions1st — correctLow effort, high leverage, fixes root cause
Few-shot examples in system prompt2ndTreats symptom, token overhead on every call
Merge tools into one3rdLoses useful semantic distinction, high refactor cost
Train a routing classifier4th — wrongExtra model call, latency, new failure point

Tool Splitting

Code smell: a tool description containing "or" between behaviours, or "depending on" between conditions. Split into purpose-specific tools with tight contracts.

Structured Error Responses

The MCP isError flag is the agent's primary recovery signal.

Four error categories agents must distinguish
CategoryExamplesRetryable?Agent Response
TransientNetwork timeout, 503, rate limitYes (same input)Backoff + retry, then escalate
ValidationWrong format, missing field, malformed IDYes (after fixing input)Correct input and retry
BusinessRefund exceeds limit, account locked, not eligibleNoSwitch workflow; surface description to user
Permission401, 403, missing scopeNo (by this agent)Escalate or request elevated creds

THE Most-Tested Distinction in 2.2

CaseResponseAgent Action
Access failure (tool can't reach source)isError: true, category transient/permissionDecide whether to retry
Valid empty result (tool queried successfully, found nothing)isError: false, empty array / null resultTell user "no results"
Critical: Conflating these is the canonical 2.2 exam trap. Returning [] for both "no such customer" AND "database unreachable" causes the agent to retry endlessly.
TS 2.3

Tool Distribution and tool_choice

Scope tools to roles. The sweet spot is 4-5 tools per agent.

The tool_choice Values

Needtool_choice Value
Model may or may not call a tool"auto" (default)
Model MUST call some tool, of its choice"any"
Model MUST call this specific tool{"type": "tool", "name": "extract_intent"}

Force-a-Specific-First-Step Pattern (Exam Favourite)

Scenario: "Every customer message must first extract intent and entities before routing. Currently done via system prompt instruction; ~15% of messages skip the extraction."

Correct fix: set tool_choice: {"type": "tool", "name": "extract_intent"} on the first turn. Switch to "auto" for subsequent turns. The model literally cannot output anything other than the forced tool call. 15% miss rate → 0%.

Key rule: When the requirement is "the model MUST do X first", reach for tool_choice: {"type": "tool", "name": "X"}, not a prompt instruction. Prompts request; tool_choice requires.

Credential handling and server configuration scoping.

Credential Handling — ${VAR} Expansion (Most-Tested 2.4 Pattern)

Wrong: hardcoding actual tokens in config files.

Right: use ${VAR} expansion and store secrets in each developer's local environment.

Rule: "shared config, personal credentials". The `.mcp.json` stays committed and shared. Secrets live in each developer's local environment. Rotate any leaked token — git history is forever.

TS 2.5

Built-in Tools: Grep vs Glob

THE most-tested distinction in this section.

Grep vs Glob decision matrix
ToolSearchesReturnsMnemonic
GrepFile contentsMatching lines + filenames"What does the code say?"
GlobFile pathsFile paths matching pattern"What files exist?"

Mirror Traps

  • "Find all React component files" → Glob **/*.tsx, NOT Grep
  • "Find all callers of formatDate" → Grep formatDate(, NOT Glob

Edit Tool Escalation Ladder

  1. Expand the old_string anchor with surrounding context until unique — the FIRST move
  2. If anchor cannot be made unique → Read + Write the full file
  3. If intent was actually "change every occurrence" → use replace_all: true
Quick Reference

One-Line Mnemonics

  • Misrouting: descriptions are the routing layer — expand them first.
  • "Or" / "depending on" in a tool description: split the tool.
  • isError: true: the tool couldn't look. isError: false + empty: the tool looked and found nothing.
  • Tool count: 4-5 per agent. More degrades selection.
  • "Must do X first": tool_choice: {"type": "tool", "name": "X"} — never a prompt instruction.
  • Credentials in committed .mcp.json: ${VAR} expansion + rotate the leaked token. Don't relocate the file.
  • Grep vs Glob: content = Grep, paths = Glob. Wrong choice = wasted time or impossible task.
  • Edit fails with "multiple matches": expand the anchor first; Read + Write only as fallback.
