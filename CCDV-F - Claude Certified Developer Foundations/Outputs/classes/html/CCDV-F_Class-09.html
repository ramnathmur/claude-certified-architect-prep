    What the SDK Is Hiding

    Underneath every SDK call is an HTTP request to an endpoint with a key and a JSON body. The SDK writes it for you. Everything it hides is still happening — and the things that break are almost always in the part it hid.

    What you leave holding
    1. SDK and raw REST reach the same API and the same model.
    2. Streaming is the same HTTP connection, delivered in pieces.
    3. "Async" means two completely different things, solving different problems.
    4. Non-blocking concurrency is not the same as batch.
    5. Batch trades up to 24 hours of latency for a lower per-token cost.

    01 · The wrapper

    SDK versus raw REST

    By the end of this screen you'll know exactly what you give up by calling the endpoint directly, which is less than people assume.

    At its core, Claude is reached over an HTTP REST API. Your code sends a request to an endpoint with your API key and a JSON body, and reads a JSON response back. You can do that with any HTTP client in any language.

    More commonly you use an official SDK — Python and TypeScript among others — which is a thin convenience layer over the same REST API.

    Worth being precise, because Class 1 introduced a differently-named thing: this is the Anthropic SDK, the ordinary client library. It has no loop and no opinions. The Claude Agent SDK is a different product entirely — the whole agent loop, the permission model, hooks. Same three letters, unrelated jobs.

    02 · How it arrives

    Synchronous, and streaming

    By the end of this screen you'll be able to pick between them on the only question that decides it.

    A synchronous request is the simplest pattern: send it, wait for the complete response in one piece, act on it. Fine for short responses, and fine for backend jobs where nobody is watching.

    Streaming sends the response in pieces as the model generates them. Output appears immediately rather than after a blank-screen wait, and your code reassembles the pieces into the final message. Claude does this over the same HTTP connection, using server-sent events.

    Notice it's not a different endpoint or a different protocol. Same connection, delivered incrementally.

    So the question that decides it is simply: is anybody watching? Streaming buys perceived responsiveness and nothing else — the total time to the last token is not shorter. If no human is waiting on the output, you have added partial-state handling to your code and bought nothing with it.

    And it does add something to handle

    A stream can be interrupted partway. Your reassembly code has to cope with an incomplete message without corrupting whatever state it was building — which is a real class of bug, and the reason streaming is a decision rather than a default. Class 12 does the mechanics.

    03 · The ambiguous word

    Two patterns, both called "async"

    By the end of this screen you'll never conflate non-blocking concurrency with batch processing again — and the exam tests exactly this distinction.

    Two patterns address high-volume work. They solve different problems, and sharing a word is the whole reason people reach for the wrong one.

    Non-blocking async

    The Python SDK exposes an async client (AsyncAnthropic) using non-blocking async/await, so calls don't tie up your application thread. In the TypeScript SDK the standard client is already Promise-based, so you await calls directly — there is no separate async client class.

    Either way the request still returns in real time. What you gain is that your application can do other work while it waits. This is the right pattern when you need concurrency without blocking.

    The Message Batches API

    A separate pattern for bulk offline workloads. You submit a large set of requests in one call, receive an identifier, and poll for completion. Jobs can take up to 24 hours and run at a lower per-token cost in exchange for that latency.

    It suits offline pipelines, evaluation runs, and bulk jobs where no user is waiting on each result and cost matters more than turnaround.

    The discriminator

    Ask who is waiting. If your application is waiting but shouldn't block — async client. If nobody is waiting until tomorrow morning — batch, and take the discount. This is one of the official sample questions on the exam, almost word for word.

    Recap

    What you're leaving with

    1. The SDK is a thin layer over REST. Same endpoint, same model, less boilerplate.
    2. Anthropic SDK is not the Agent SDK. One is a client library; the other is a whole agent loop.
    3. Streaming is the same connection, delivered in pieces, and buys perceived responsiveness only.
    4. Non-blocking async frees your thread. Real-time responses, same price.
    5. Batch trades up to 24 hours for a lower per-token cost. Only where nobody is waiting.
    Before Class 10

    A service re-scores every item in a 400,000-row catalogue each night, writing results to a warehouse table that a dashboard reads in the morning. The current implementation fires synchronous calls in a loop and takes eleven hours. An engineer proposes switching to the async client so the calls run concurrently.

    Will that work? And is it the right answer?

    It will work, and it is the wrong answer. Async concurrency genuinely fixes the stated symptom — eleven hours is mostly the thread sitting idle waiting on responses, and running them concurrently will collapse that dramatically.

    But look at what the scenario actually says. The results are read in the morning. Nobody is waiting on any individual score. That is the batch shape exactly, and batch buys the same overnight completion at a lower per-token cost — which async does not, because async changes your threading model and leaves your bill alone.

    This is the trap worth recognising: the async proposal solves a real problem, which is what makes it convincing. It just isn't the problem the constraint points at. The exam's distractors are built exactly this way — legitimate techniques that don't match the stated constraint. Here the constraint is "results not needed until morning," and that word selects batch.
