| Claude Fable 5.1 | claude-fable-5-1 | demanding reasoning, long-horizon agentic work | $10 / $50 | slower | high |
| Claude Opus 5.5 | claude-opus-5-5 | long-running agentic coding and knowledge work | $4 / $20 | moderate | medium |

- Batch API requests are 50% cheaper. Prompt-cache reads cost 10% of the base input price, except 2.5% on Fable 5.1 and 5% on Opus 5.5 and Sonnet 5.5.

## Thinking (https://platform.claude.com/docs/en/build-with-claude/extended-thinking and /context-windows)

- Manual extended thinking is `thinking: {type: "enabled", budget_tokens: N}`. Minimum budget 1,024 tokens. The budget must be below `max_tokens` (the exception is interleaved thinking in manual mode). The budget is a target, not a hard cap.
- Status on the page read today: deprecated on the Claude 4.6 models; Claude 4.7 and later models reject it with a 400 error. The replacement is `thinking: {type: "adaptive"}` with depth set by `output_config: {effort: ...}`.
- Thinking tokens are billed as output tokens, count toward `max_tokens` and the context window, and are reported in `usage.output_tokens_details.thinking_tokens`.
- With tool use, the whole unmodified thinking block, signature included, goes back with the tool result.
- On current models previous thinking blocks stay in context by default and count as input.
- Changing the manual budget (or the effort level in adaptive mode) invalidates message-level cache breakpoints.

## Prompt caching (https://platform.claude.com/docs/en/build-with-claude/prompt-caching; first 100,000 of 162,264 characters read)

- The prefix is built in the order tools, system, messages. A change at one level invalidates that level and every later level: a tool-definition change invalidates all three, a system-prompt change invalidates system and messages. A `tool_choice` change or adding or removing images affects only the message blocks. A change to thinking parameters or `output_config.effort` invalidates message blocks.
- Minimum cacheable prompt: 512 tokens on Fable 5.1, Opus 5.5, Sonnet 5.5 and Haiku 5.5; 1,024 on Sonnet 4.6, Sonnet 4.5, Opus 4.8 and Sonnet 5; 2,048 on Opus 4.7 and Haiku 3.5; 4,096 on Opus 4.6, Opus 4.5 and Haiku 4.5. A shorter prompt runs uncached and returns no error.
- Lifetime: 5 minutes by default, 1 hour by adding `"ttl": "1h"` to `cache_control` (`{"type": "ephemeral", "ttl": "1h"}`). Each use refreshes the lifetime at no extra cost.
- Price multipliers on the base input price: 5-minute write 1.25x, 1-hour write 2x, read 0.1x (0.025x on Fable 5.1, 0.05x on Opus 5.5 and Sonnet 5.5).
- Up to 4 cache breakpoints per request.
- Usage fields: `cache_creation_input_tokens` (written), `cache_read_input_tokens` (read), `input_tokens` (after the last breakpoint), and a `cache_creation` object with `ephemeral_5m_input_tokens` and `ephemeral_1h_input_tokens`.

## Context window (https://platform.claude.com/docs/en/build-with-claude/context-windows)

- 1M tokens is the default window on the four current models (no beta header); long-context requests are billed at standard pricing, except Haiku 5.5 prompts above 100,000 tokens cost more. Maximum output per request 128K tokens.
- Everything counts toward the window: system prompt, every message including tool results, images and documents, tool definitions, and the model's output including thinking. Cached prefixes still count; caching changes the price, not the size.
- The page names "context rot": accuracy and recall degrade as the token count grows, so curating context matters as much as having room.
- Long conversations: server-side compaction is the primary strategy (beta, Claude 4.6 and later); context editing offers tool-result clearing and thinking-block clearing.
- Overflow: an input already over the window returns a 400 `invalid_request_error` ("prompt is too long"). On 4.5-and-newer models, input plus `max_tokens` over the window is accepted and generation can stop with `stop_reason: "model_context_window_exceeded"`.

## Prompting guidance (https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices; the older long-context-tips and multishot-prompting URLs now land on this page)

- Examples should be relevant, diverse (edge cases, enough variety to avoid unintended patterns) and structured (each in `<example>` tags, several in `<examples>`). The page says "Include 3-5 examples for best results".
- Inputs of 20k tokens or more: put long documents near the top, above the query, instructions and examples. Queries at the end can improve quality by up to 30 percent in the page's tests, most for complex multi-document inputs. Wrap each document in `<document>` with `<source>` and `<document_content>` subtags. Ask Claude to quote the relevant parts first.
- Worked examples also shape how Claude reasons inside its thinking.

## Agent Skills (https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)

- A Skill is a directory with a `SKILL.md` file, loaded in three levels (progressive disclosure): level 1 metadata (`name` and `description`) always loaded, about 100 tokens per Skill; level 2 the `SKILL.md` body when the Skill triggers, under 5k tokens; level 3 bundled files and scripts only when needed (scripts run through bash and only their output enters context).
- Frontmatter limits: `name` at most 64 characters, lowercase letters, numbers and hyphens only, no XML tags, no reserved words "anthropic" or "claude"; `description` non-empty, at most 1,024 characters, no XML tags, and it must say what the Skill does and when to use it.
- Surfaces and sharing: Claude API (needs the code execution tool; custom Skills shared workspace-wide; sandbox with no network and no runtime package installs; the Skills API has a version download endpoint); Claude Code (filesystem, `~/.claude/skills/` personal or `.claude/skills/` project, shareable through plugins; full network access); claude.ai (zip upload, individual user only, not shared org-wide). Custom Skills do not sync across surfaces.
- The page warns to use Skills only from trusted sources and to audit them like installed software.
