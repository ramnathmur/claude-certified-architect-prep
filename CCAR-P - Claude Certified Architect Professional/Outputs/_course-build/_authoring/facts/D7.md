## Memory and CLAUDE.md (https://code.claude.com/docs/en/memory)
- "Claude treats them as context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead."
- CLAUDE.md locations, in load order from broadest to most specific: managed policy (org-wide, for example /etc/claude-code/CLAUDE.md on Linux), user (~/.claude/CLAUDE.md, only you, all projects), project (./CLAUDE.md or ./.claude/CLAUDE.md, shared via source control), local (./CLAUDE.local.md, personal, gitignored). A project instruction appears in context after a user instruction.
- Files in the directory hierarchy above the working directory load at launch; files in subdirectories load on demand, once Claude reads or edits a file there. "All discovered files are concatenated into context rather than overriding each other." Order: filesystem root down to the working directory.
- "if two instructions contradict each other, Claude may pick one arbitrarily."
- Size: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." Move part-of-codebase instructions into path-scoped rules.
- `@path/to/import` syntax; relative paths resolve from the containing file; max depth four hops.
- `.claude/rules/*.md`, discovered recursively; rules without `paths` frontmatter load at launch with the same priority as .claude/CLAUDE.md; rules with `paths` (glob patterns, YAML list or comma-separated) load when matching files are opened.
- Auto memory: notes Claude writes itself; first 200 lines or 25KB load each session.
- Settings vs CLAUDE.md: "Use settings for technical enforcement and CLAUDE.md for behavioral guidance"; block tools, commands or paths with managed settings `permissions.deny`.
- Skills load only when invoked ("use skills instead" for task-specific instructions).

## Skills (https://code.claude.com/docs/en/skills; first 100,000 of 118,114 characters)
- Locations: enterprise (managed settings), personal ~/.claude/skills/<name>/SKILL.md (all your projects), project .claude/skills/<name>/SKILL.md (commit it so the team gets it). Plugin skills are namespaced.
- Precedence on a name collision: "Enterprise over personal, and personal over project." With `deploy` in both, `/deploy` runs the personal one. A skill beats a same-named file in .claude/commands/.
- Frontmatter, all optional, only description recommended: name, description, when_to_use (appended to description; combined text capped at 1,536 characters in the listing), allowed-tools ("Tools Claude can use without asking permission during the turn that invokes this skill"), disallowed-tools ("Tools removed from Claude's available pool while this skill is active"), disable-model-invocation, user-invocable, context ("Set to fork to run in a forked subagent context"), agent, background, and others.
- Descriptions are always in context; the full skill loads when invoked. With disable-model-invocation: true the description is not in context.
- "Custom commands have been merged into skills." .claude/commands/deploy.md and .claude/skills/deploy/SKILL.md both create /deploy.
- DIFFERENCE FROM THE CORPUS: the page describes allowed-tools as pre-approval (tools usable without asking permission), and disallowed-tools as removal from the pool. The corpus row (F-7.2-01) says to scope allowed-tools to stop a skill using a tool. Teach the corpus row, add the dated note.

## Hooks (https://code.claude.com/docs/en/hooks-guide)
- Hooks are user-defined shell commands run at lifecycle points, "which gives you deterministic control: certain actions always happen rather than relying on the LLM to choose to run them."
- Configured in settings files (~/.claude/settings.json user, .claude/settings.json project, and others).
- PreToolUse runs before a tool call and "Can block it": a script that exits with code 2 blocks the action, and its stderr becomes Claude's feedback; alternatively exit 0 with JSON `permissionDecision: "deny"`.
- With several PreToolUse hooks, "the most restrictive answer applies, in the order deny, defer, ask, allow."
- Prompt-based and agent-based hooks exist for decisions needing judgment.

## CLI reference (https://code.claude.com/docs/en/cli-reference), read 2026-10-27
- `claude -p "query"` / `--print`: print response without interactive mode ("Query via SDK, then exit"); `cat logs.txt | claude -p "explain"` pipes content.
- `--output-format`: print mode only, options `text`, `json`, `stream-json`.
- `--json-schema`: "validated JSON output matching a JSON Schema after the agent completes its workflow (print mode only)".
- `--permission-mode` accepts `default`, `acceptEdits`, `plan`, `auto`, `dontAsk`, `bypassPermissions`.
- Batch API: requests are 50% cheaper (Anthropic models overview, read 2026-10-25).
