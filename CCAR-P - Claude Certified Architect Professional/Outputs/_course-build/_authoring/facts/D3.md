## Tool definitions (https://platform.claude.com/docs/en/agents-and-tools/tool-use/define-tools)

- A user-defined tool has `name` (regex `^[a-zA-Z0-9_-]{1,128}$`), `description` ("what the tool does, when it should be used, and how it behaves"), `input_schema` (JSON Schema) and optional `input_examples`.
- With the `tools` parameter, the API builds a special system prompt from the tool definitions, tool configuration and any user system prompt. So definitions are input tokens on every request.
- Best practices on the page: descriptions are "by far the most important factor in tool performance"; explain what the tool does, when to use it and when not, what each parameter means, caveats; "at least 3-4 sentences" per description, more if complex. Consolidate related operations into fewer tools (one tool with an `action` parameter instead of create/review/merge tools); fewer, more capable tools reduce selection ambiguity. Prefix tool names with the service when tools span services (for example `github_list_prs`). Return only high-signal information in tool responses.
- `input_examples` add prompt tokens: about 20 to 50 tokens for simple examples, about 100 to 200 for complex nested objects.
- `tool_choice`: `auto` (default with tools), `any`, `tool`, `none`. Forcing a tool skips thinking; on Opus 5.5, Sonnet 5.5, Fable 5.1 `any` and `tool` return a 400 error (use `auto` with strict tool use). A change to `tool_choice` invalidates cached message blocks but not cached tool definitions or system prompt.
- The page links a tool search tool and a `defer_loading` property (tool definitions loaded on demand).

## MCP architecture (https://modelcontextprotocol.io/docs/learn/architecture), read 2026-10-26

- MCP host (the AI application, for example Claude Code) creates one MCP client per MCP server; each client keeps a dedicated connection.
- Two layers: a data layer (JSON-RPC 2.0, discovery, primitives, notifications) and a transport layer. Two transports: stdio (local processes on the same machine) and Streamable HTTP (remote; supports bearer tokens, API keys, custom headers; "MCP recommends using OAuth to obtain authentication tokens").
- Three server primitives: tools (executable functions an AI application can invoke), resources (data sources providing contextual information), prompts (reusable templates). Each primitive has list methods for discovery (`tools/list`, `resources/list`) and the listings can be dynamic; tools are run with `tools/call`.
- Protocol version on the page: 2026-07-28. The protocol is stateless (every request carries the information needed); `server/discover` lets a client learn a server's capabilities. Client primitive "sampling" is deprecated as of that version.
- "Clients that federate many servers can use progressive tool discovery rather than loading every tool upfront."

## MCP in Claude Code (https://code.claude.com/docs/en/mcp), read 2026-10-26 (first 100,000 of about 150,000 characters)

- `claude mcp add --transport http <name> <url>` for remote servers (recommended); stdio for local processes (`claude mcp add <name> -- <command>`); SSE transport deprecated.
- Scopes: local (default, current project, stored in `~/.claude.json`), project (shared through `.mcp.json` in the project root; interactive sessions prompt for approval before using project-scoped servers), user (all your projects).
- Tool search is described as the default way to scale with many MCP tools. Output warning above 10,000 tokens; default limit 25,000 tokens (`MAX_MCP_OUTPUT_TOKENS`).
- Warning: "Verify you trust each server before connecting it. Servers that fetch external content can expose you to prompt injection risk."
