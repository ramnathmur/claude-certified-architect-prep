A research brief splits into four independent threads. One agent that takes them in turn needs 40, 55, 35 and 50 seconds, so the report arrives after 180 seconds. Four agents working at once, one branch each, finish when the slowest branch does, after 55 seconds. The price is tokens (words and word parts): typically four to five times a single agent's spend, because context one agent held once is duplicated across every agent.

The multi-agent design in the corpus has one coordinator and several subagents. The coordinator divides the task, hands out the parts and brings the results together. Subagents never talk to one another. Every message passes through the coordinator, an arrangement called hub-and-spoke.

Find the reason the scenario gives for more agents before adding any. After a defect, ask what the coordinator did before asking what a subagent did, because each subagent sees only what the coordinator gave it.

Add agents only for a reason the scenario states§1.5

The corpus accepts three reasons for more than one agent, and the scenario must state at least one. The first is parallelism under a latency requirement, which buys wall-clock time. The second is context isolation. The third is privilege separation. If the scenario states none of them, a single agent with the right tools is the answer.

Suppose each of four research threads adds 30,000 tokens of material. A single agent then holds 120,000 tokens when it begins to synthesise, with thread one's material still in the window while it reasons about thread four. Four isolated agents hold 30,000 each, which keeps every window small even though the total across agents is higher, and a synthesis agent receives four structured summaries, compact records with named fields, instead of four transcripts.

Privilege separation is set in configuration: the drafting role is built without a write tool, and the verifying role without a search tool. Every split also adds a handoff between the coordinator and a subagent, and each handoff loses information. A direct channel between subagents would dissolve both the isolation and the privilege boundary, and the token cost would remain.

That makes multi-agent the most expensive rung of the pattern ladder, so only the three reasons justify the climb. A sequential task has no independent branches to run together, and where cost is the named pillar the multiplier works against it. The corpus gives stakeholders one sentence: "We pay more tokens to buy wall-clock time and clean separation of privilege."

This is not a corpus rule. In Anthropic's post "How we built our multi-agent research system" (13 June 2025), "agents typically use about 4× more tokens than chat interactions" and multi-agent systems "use about 15× more tokens than chats".

Those baselines are chats, and the corpus's 4 to 5× is measured against a single agent. Dividing the two figures gives 3.75. The post does not state that ratio, so this is an inference, and it lands just under the corpus range.

The post says multi-agent systems "excel at valuable tasks that involve heavy parallelization, information that exceeds single context windows, and interfacing with numerous complex tools". Parallelism and context isolation appear in the corpus list too. It names as poor fits the problem areas that "require all agents to share the same context or involve many dependencies between agents".

Its cost condition is that the task's value be "high enough to pay for the increased performance", which is the corpus's rule that the multiplier needs funding.

Ask what the coordinator did before blaming a subagent§1.6

The coordinator owns four things. Decomposition is how it splits the task before delegating, for example into distinct subtopics or source types. Context passing is what each subagent receives, and in what form. Error handling is what happens when a subagent fails. Termination criteria say when the work stops. A subagent's context is isolated, so it knows only what the coordinator passed it.

Because the coordinator owns those four things, an output-level symptom in a multi-agent system usually traces to it and not to a subagent. A subagent that returned correct results on the ground it was assigned, meaning its part of the task, has done its job. A wrong report then points at how the parts were assigned, what was passed, how failure was handled or when the loop stopped.

Three terms in the rules below need a gloss. A prompt is procedural when it lists steps, and goal-oriented when it states the goal and the quality criteria. With structured error propagation, a failure returns to the coordinator as data it can act on. A recovery policy is the coordinator's rule for what happens next: retry, skip or escalate.

The Task-equivalent is the capability that lets a coordinator start subagents at all. When it is missing from the coordinator's configuration, there is nothing to delegate with.

A subagent definition takes a description, a prompt and an optional list of tools, among other fields. A tool left out of that list "isn't in the subagent's session at all", with "no permission prompt or error". That is removal by configuration, the form of least privilege that §3.2 requires.

The page also says that an ordinary subagent starts with a fresh context window. The only content passed down is the Agent tool's prompt string, and only the subagent's final message comes back. A fork, which copies the parent conversation, is the exception. These two narrow channels are where handoff loss happens, which is why §1.7 is about the passing format.

The runtime does not enforce the corpus's topology. The page says a subagent can spawn subagents of its own, with 3 layers below the main agent allowed by default, and that a subagent given the SendMessage tool is told the names of other agents it can message. Hub-and-spoke is a design choice made in configuration.

The page's advice for a coordinator that answers directly instead of delegating is to name the subagent in the prompt and write a clear description. Inference: that advice suits a coordinator that has the tool and leaves it unused, while the corpus row covers the case where the tool is absent.

Pass findings with their sources attached§1.7

A synthesis agent can cite only what reaches it as a separate field. So the coordinator passes each finding as content plus metadata: its provenance, meaning source URL, document name, page and date. Merge the two into free text during aggregation and attribution, the link from a claim to its source, is lost. An instruction to cite cannot restore it, because the agent cannot cite metadata it never received.

Conflicts and audits depend on the same separation. When two sources report different values, keep both with their attribution and mark the conflict. The coordinator decides which to use. A regulated audit trail needs the citation, the input and the prompt version, and flattened provenance loses all three.

The receiver of a handoff can also be a person. A human who receives an escalation does not have the transcript, so the handoff summary must stand alone. It carries the entity ID, an issue summary, the root cause, the actions already taken, the amount or quantity at stake, the recommended action and the reason for escalating.

A gap in the synthesis goes back to the coordinator, which sends targeted queries and runs the synthesis again. With only 3 of 5 sources returned, failing the run discards three good sources. The coordinator synthesises instead, with coverage annotations that mark what is well supported and what is missing. That is graceful degradation.

Zero results from a subagent is a finding. Read zero results as a timeout and the coordinator retries for nothing. Read a timeout as zero results and an access failure goes unreported as an empty finding.

Fan out what is independent and chain only real dependencies§1.8

Three shapes cover the choices. In parallel fan-out the coordinator sends independent subtasks out together. In sequential chaining step B needs step A's extracted entity, which is a real data dependency. Iterative refinement repeats a loop when one pass cannot guarantee coverage. Serialise only what depends on an earlier result, and send everything else out in one turn.

Parallel delegations must be issued in a single coordinator turn. The Agent SDK documentation defines a turn as one round trip: the coordinator produces output that includes tool calls, the tools run, and the results feed back to it.

The corpus rule is that delegations spread across turns run one after another and raise no error. Issued over four turns, the four research branches take 40 + 55 + 35 + 50 = 180 seconds again.

The refinement loop runs delegate, synthesise, evaluate for gaps, re-delegate targeted queries and re-synthesise. The coordinator needs sufficiency criteria to know when to stop. An iteration cap is a safety net that limits spend and says nothing about quality, so a loop that never ends is missing criteria, and a tighter cap does not supply them.

The coordinator's prompt states goals and quality criteria and gives no step-by-step procedure. A prompt that dictates the steps leaves the coordinator nothing to decide, and the research it directs comes out shallow and checklist-shaped, as in the last row of §1.6.

Go deeper: a refinement loop, and turns in the Agent SDK

This is a worked example, not a corpus rule. A coordinator researches five subtopics and states two criteria: each subtopic has at least two independent sources, and no two findings conflict without an annotation. After the first pass, subtopics one to three have two sources each, subtopic four has one and subtopic five has none, so 40% of the subtopics fail the first criterion.

The coordinator sends two targeted queries in one turn, runs the synthesis again and checks again. When every subtopic has two sources and no conflict is unannotated, the loop ends. A cap of five passes stands behind this as a safety net. If the cap ends the run instead, the report may still miss the criteria, and the cap has judged nothing about it.

The Agent SDK pages read for this chapter (25 October 2026) list safety nets of this kind: a maxTurns limit, a spend cap (maxBudgetUsd) that counts subagent spend, and limits on subagent nesting depth and concurrency. These bound a run and judge nothing about the report.

The subagent page also says a subagent the main agent spawns runs in the background by default, with its report arriving in a later turn, and that Claude waits when its next action needs the report. Inference: whether delegations issued one per turn run in series therefore depends on the runtime and on whether the coordinator waits. The exam rule stays as the corpus states it: issue independent delegations together.

Design shapeHuman agents receiving escalations keep asking customers for details the system already collected. Giving the humans the raw transcript is DISCARD: it replaces a compact designed artifact with the whole history, which they must now read end to end.

Escalating earlier is WRONG-AXIS, because the context would still not be transferred, and it lowers the autonomous resolution rate.

A billing dispute with three independent issues is investigated one issue at a time. The answer decomposes it into three issues and dispatches them from a single coordinator turn, with shared customer context, then synthesises one resolution. A faster model is WRONG-AXIS, because it shortens each call and leaves the serial order in place. Dispatching across three successive turns is HALF-MOVE: the decomposition is right and the execution is still sequential.

Say it backA research report leaves out whole subtopics, yet every subagent's output is correct. One colleague proposes better search queries for the subagents, another proposes more subagents. Where does the fix go, and why do both proposals miss?

The fix goes in the coordinator: widen its decomposition and have it partition the whole space explicitly before it delegates. The subagents did their job on the ground they were assigned, so better queries cannot reach ground nobody assigned. More subagents on the same narrow partition repeat the same gap.

Remember

  1. More than one agent needs a reason the scenario states: parallelism under a latency requirement, context isolation, or privilege separation. With none, use one agent. The price is typically 4 to 5 times the tokens, plus information loss at every handoff.
  2. Hub-and-spoke: subagents never talk to each other. The coordinator owns decomposition, context passing, error handling and termination, so an output defect usually traces to it.
  3. A subagent knows only what the coordinator passed. Pass findings as content plus metadata, because an instruction to cite cannot restore metadata that never arrived.
  4. A human receiving an escalation has no transcript, so the handoff summary stands alone. With partial inputs, synthesise and annotate coverage. Zero results is a finding; a timeout is an access failure.
  5. Independent work fans out in a single coordinator turn. Chain steps only on a real data dependency. Across turns, delegations run in sequence and no error appears.
  6. Refinement ends on stated sufficiency criteria, and the cap is a safety net. The coordinator's prompt states goals and criteria, never steps.
