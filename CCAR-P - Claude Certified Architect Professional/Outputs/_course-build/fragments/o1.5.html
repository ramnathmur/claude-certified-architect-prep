Suppose a pull request touches 14 files and about 800 changed lines, an average of 57 lines per file. One prompt reads the whole diff and returns one verdict. The review comes back shallow, and it approves a pattern in one file that it flagged in another.

Decomposition is the repair: split the task into units that each get one job. Most of Domain 1 uses it. A workflow splits a task into steps, an architecture splits a system into stages, and a multi-agent system splits it into roles.

Cut where two criteria meet, and stop when handoffs cost more§1.11

A task left in one unit fails in four ways. The first is attention dilution: a pass over many inputs goes deep on some and shallow on others, and you cannot predict which. The second is mixed criteria. If one unit is judged on accuracy, tone and completeness together, a failing score does not say which of them failed.

The third is that a partial failure cannot be recovered, because the single call is redone whole. The fourth is that there is no seam: no boundary where a validation, an approval or a cost control could attach.

The corpus gives one granularity rule. Split until each unit has one evaluation criterion (the one question its output is judged on) and one failure mode (the one way it can go wrong). Stop when the overhead of the handoffs exceeds the benefit. A unit with one criterion tells you what to fix when quality drops.

Cut where two criteria meet or where a gate has to go in. A natural-sounding process name is no reason to cut. The review in the figure splits at the one place where two criteria meet: local correctness, judged file by file, and cross-file consistency, judged once over the results by an integration pass.

There are five ways to cut. A functional split follows the stages of a process, such as extract, validate, enrich and format. An aspectual split sends the same input through different lenses, such as a security pass and a style pass. A data-partition split divides a corpus into chunks, as in a per-file pass followed by a cross-file pass.

The remaining two cut by the case in front of you. A confidence-tier split sends routine cases down a cheap path and hard cases down an expensive one, and it is the main architectural lever on cost. A risk-tier split follows blast radius, meaning how much damage a wrong action does and whether it can be undone. Reversible actions run on their own, and an irreversible one waits at a gate.

The two tiers answer different questions. Difficulty sets the confidence seam and is what moves cost. Blast radius sets the risk seam and is what governs autonomy. A scenario that names cost as its pillar calls for the first, and one that mixes routine actions with a single action nobody can undo calls for the second.

Separately from where to cut, the plan has a shape. A fixed pipeline suits a scope you know in advance, and it is predictable and reproducible. Dynamic adaptive decomposition generates subtasks from what the earlier steps find, which suits an open-ended investigation. A review that always follows the same template gets the fixed pipeline, because adaptivity there adds nondeterminism, meaning results that can differ between runs, for nothing.

What crosses a seam is a structured summary: issues found, exported symbols changed, dependencies touched. If the integration pass instead receives all 14 raw diffs, it carries the same dilution the split existed to remove. Every handoff also loses context that was implicit in the shared context window. A design split so finely that later steps lack what earlier ones knew should be merged. Over-decomposition is a real defect.

Go deeper: the review and the tiers in numbers

A worked example with invented figures, not a corpus rule. Suppose each per-file call takes 20 seconds. Fourteen in sequence take 280 seconds. Fanned out in parallel, the wall clock is the longest branch, 20 seconds, and a 25-second integration pass brings the review to 45 seconds. Each call also reads about 57 lines instead of 800.

A second example, again with invented prices. Take 10,000 cases a month, 90% of them routine, at $0.02 a case on the expensive path and $0.002 on the cheap one. Everything on the expensive path costs $200.

Split by tier, the9,000 routine cases cost $18 and the 1,000 hard ones cost $20, a total of $38 plus the cost of the triage step. The saving holds only while triage costs less than the $162 it saves.
