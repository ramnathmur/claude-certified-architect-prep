A claims workflow has ten steps. Tested on its own, each step is right 96% of the time, and every step passes its test. End to end, the workflow is right only about 66% of the time. No step is the culprit, and the team's reflex is to find a better model.

That is one risk among several that this objective names. A second is an agent that follows an instruction hidden in a document it was asked to summarise. A third is a fluent figure that nobody can tell is invented. Each has a signature, a structural control and a wrong control that looks the same from a distance.

Read the symptom's timing before blaming the model§5.6

Reason from when and where the failure appears. A capability explanation that ignores the timing is almost always wrong. The corpus gives six signatures. Confidently wrong right after a content refresh points at retrieval and indexing, and not the model's reasoning. No memory of something said two turns earlier, in a short conversation, is the application not resending history, and not an exceeded window.

Quality that degrades only on long inputs, on mid-document content, is uneven attention across position and not input length alone. Behaviour that changed with no code deployment is model version drift and not a prompt regression. An agent that took an unrequested action after processing an external document is an indirect prompt injection and not user error. A pipeline where every step passes its own test, with far lower end-to-end accuracy, is compounding across steps.

For a ten-step agent at 96% per step delivering about 66% end to end, insert deterministic validation checkpoints mid-chain. They interrupt the compounding, and a better model shifts each step only marginally.

If the same prompt and code behave differently this week, check the pinned model version and run the regression set, since, with the code unchanged, drift is the explanation the corpus gives, after any change in data or traffic has been ruled out. A RAG answer that turned confident and wrong the day the corpus was re-indexed points at chunking, embedding version and index freshness.

In a risk register, rank by consequence and reversibility, and not by frequency alone. A rare irreversible action ranks above a frequent recoverable one.

Go deeper: why a slightly better model does not rescue the chain

This is a worked example, not a corpus rule. Lift each step from 96% to 97% and the ten-step chain rises from 66% to 74%. A one-point gain per step still leaves about one task in four wrong.

A deterministic checkpoint in the middle of the chain does something different: it stops an error from being carried into the later steps, where it can multiply. The corpus prefers it for that reason.

Remove the privilege that an injection would hijack§5.7

Instructions and data share one channel, so any text the model reads can try to act as an instruction. Indirect injection arrives through retrieved web pages, PDFs, support tickets, code comments, calendar invites and email bodies. The failure looks like a legitimate tool call that no user asked for. The structural control is to remove privilege from the model and to validate the requested action, not the text that requested it.

If an agent summarises third-party documents and holds a tool that can send email, remove the send capability or require human approval on send. An injection then has no privileged action to hijack. A filter for known injection phrasings stays as a layer and is rejected as the control, because novel phrasings pass and the capability is untouched.

When retrieved content must go into the context, wrap it in a delimited block that the system prompt declares to be data, and never let eligibility or authorisation decisions depend on its contents. That reduces the attack surface without pretending the channel is separated. For an agent that handles only internally authored, access-controlled content and holds no external tools, delimiting plus input validation is proportionate, since a human gate would cost more than the risk.

Verify from outside the model§5.9

Catching confident but wrong output needs verification that is independent of the model. A check is independent when it can fail while the model succeeds and succeed while the model fails. A check that draws on the same process cannot do that. Asking the same model to double-check, making a second call with the same context, and trusting a self-reported confidence score are all not independent.

Verification pays most immediately after steps whose errors are cheap to detect and expensive to propagate. If extracted figures must match the source document, compare them deterministically against the structured source, which fails independently of the generation.

If cited policy clauses must exist, look each citation up in the policy database before release. For free-text summary quality with no ground truth, use a second-model or rubric-based check and state its correlation limits. It is the best available and not a guarantee.

A self-critique pass to catch hallucination is accepted as a quality improvement and rejected as the control, since it reduces the rate and shares the failure mode.
