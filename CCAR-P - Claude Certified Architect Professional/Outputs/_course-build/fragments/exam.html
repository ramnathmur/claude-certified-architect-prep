The three published samples

The guide prints three sample questions, one each from Domains 3, 2 and 4, and says they are illustrative and not drawn from the live item bank. They are paraphrased here. Decide on your answer, then open the reveal.

Sample 1, Domain 3: Integration

A support agent can read tickets, draft replies, issue refunds and delete accounts. Staff only ever read tickets and draft replies. Applying least privilege, which change reduces risk most?

  1. Add logging to the refund and delete tools so misuse can be audited.
  2. Remove the refund and delete tools from the agent's configuration.
  3. Keep all the tools and add a confirmation prompt before refunds and deletions.
  4. Replace the agent with a larger model that follows instructions more reliably.
AnswerOpen once you have chosen.

B. Least privilege means removing capabilities the role does not need, which shrinks the attack surface instead of watching it. Logging and confirmation prompts are detective or compensating controls, and model size has nothing to do with authorization scope. This project tags options A and C DETECTIVE-FOR-PREVENTIVE. The idea is taught in O3.2.

Sample 2, Domain 2: Models, Prompting and Context

An application sends the same 8,000-token system prompt and policy document on every request, followed by a short, varying user message. Latency and cost both matter. Which optimization addresses both most directly?

  1. Truncate the policy document to its first 1,000 tokens.
  2. Switch to the smallest available model regardless of fit.
  3. Put the static system prompt and policy before the dynamic content, and enable prompt caching.
  4. Move the policy document into a few-shot example block.
AnswerOpen once you have chosen.

C. Stable content first, with caching on, lets the repeated prefix be reused, which cuts both time to first token and cost without discarding required context. Truncating loses needed policy, a blindly smaller model risks quality, and a few-shot block does not create a reusable prefix. This project tags the truncation option DISCARD, because it throws away policy the answer needs. The idea is taught in O2.5.

Sample 3, Domain 4: Evaluation and Optimization

A RAG system suddenly returns confident but incorrect answers after a document refresh, while latency and model version are unchanged. Where do you look first?

  1. The model weights have silently changed.
  2. The retrieval and indexing step is returning irrelevant or stale chunks.
  3. The temperature setting is too low.
  4. The context window has shrunk.
AnswerOpen once you have chosen.

B. Confident wrong answers right after a refresh, with the model and latency unchanged, point at retrieval feeding the model poor context, for example a broken re-index or mismatched embeddings. The other causes would not be triggered by a refresh, and the stem says the model version is unchanged.

This project tags A, C and D EVIDENCE-MISMATCH, because the stem's evidence does not support them. A wrong option can fit more than one family, and the project's own scenario for the same failure tags the temperature option WRONG-AXIS. The mechanism is taught in O3.5 and the diagnosis order in O4.4.

Read together, the three rationales reward three habits: remove what the role does not need, put stable content first so it can be reused, and look first at the layer that changed.
