Domain 2 carries 13% of the exam, about 8 of the 63 items, across five objectives. Domain 1 chooses the design. Domain 2 fills each request that design sends: which model reads it, which instructions and examples go in it, what history travels with it, and which parts were reused from earlier requests.

Most scenarios here describe a symptom, such as inconsistent output, a forgotten fact, a missed finding or a rising bill, and ask which part of the request to change. The table below is the course's reading of the domain, not the guide's wording.

ObjectiveThe question it answers
Model selectionWhich model carries this task at this cost and latency?
System prompts and guardrailsWhere does each rule live so that it holds on every turn?
Prompting techniquesDoes the failure call for examples or for a reasoning cue?
Context windows and tokensWhat does each call carry, and where does each part sit?
Prompt reuseWhat can be reused across requests and across teams?

The one official Domain 2 sample is about prompt caching. The right answer puts the static prompt and policy before the dynamic content and enables caching, and the wrong answers truncate the policy, pick the smallest model or move the policy into a few-shot block. It is worked through in the last chapter of the domain.

Two points differ from Anthropic's current documentation, and the chapters mark each with a date. The corpus names 4 to 6 targeted examples where the live prompting page says 3 to 5. The corpus also teaches extended thinking, where the live pages call the manual form deprecated and describe adaptive thinking in its place. Answer exam items with the corpus.
