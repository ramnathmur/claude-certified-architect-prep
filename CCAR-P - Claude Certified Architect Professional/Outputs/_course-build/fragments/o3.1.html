An operations agent has collected 22 tools over three quarters, because each new integration was added to the agent that already existed. Each tool definition, with its name, description and input schema, averages about 200 tokens. The agent therefore carries 4,400 tokens of definitions before it reads a word of the request. At 40,000 requests a day, that is 176,000,000 tokens a day spent describing tools.

A week of traces shows the misroutes sitting in three near-duplicate pairs: get_customer with get_account, search_tickets with search_knowledge, and send_notification with create_alert. On requests that touch those pairs the agent picks the wrong tool 11% of the time. On the other sixteen tools the rate is under 2%. The figures are illustrative.

Shrink the decision space before polishing descriptions§3.1

A tool costs three things. It costs tokens on every request, because tool definitions are a fixed per-request tax paid whether the tool is called or not. It costs discrimination on every turn, since the model must pick between candidates by reading their descriptions. And it costs blast radius when misused, since every tool is also a capability the agent can use.

Misroutes concentrate in near-duplicate pairs, and the error rate rises faster than the tool count. Pairs grow faster than tools, because each new tool can pair with every tool already there: 10 tools make 45 possible pairs, and 22 tools make 231.

The corpus discriminator is whether the failure comes from the size of the decision space or from the quality of individual descriptions. Cut the number of candidate tools first. Sharpen descriptions only for the confusable pairs that survive the cut.

With 20 or more tools spanning several unrelated roles, split into role-scoped agents of 4 to 6 tools each. That moves confusable pairs into different agents, and the discrimination problem disappears where mitigation would only shrink it. If two tools inside one scoped agent are still confused, expand both descriptions with input formats, boundaries and when-not-to-use. Once the decision space is small, descriptions are the primary selection lever.

A generic tool such as fetch_url, used outside its intended scope, is replaced with a constrained tool that validates its own inputs. The boundary then holds at the interface, where an instruction in a prompt would hold it only probabilistically.

One exception is sanctioned. A scoped agent that needs a simple cross-role lookup on nearly every turn gets a narrowly scoped cross-role tool, because coordinator round-trips on a high-frequency need cost more than the scoping saves. Complex cross-role cases still route through the coordinator.

A stakeholder may ask to keep every tool available "for flexibility". Push back with the per-request token cost and the measured misroute rate. Flexibility on a tool surface cannot be told apart from ambiguity.

Go deeper: the arithmetic of the split, and what Anthropic's documentation says about descriptions

This is a worked example, not a corpus rule, and the 200 tokens a tool is an assumption. The largest of the four agents has 6 tools, which is 1,200 tokens of definitions. Against 4,400, each request saves at least 3,200 tokens. At 40,000 requests a day, that is 128,000,000 tokens a day, before any gain from fewer wrong tool calls.

The figure ignores the routing step that picks an agent for each request. Its tokens, time and own misroute rate have to be counted before the saving is claimed.

Anthropic's documentation on defining tools (live docs, read 2026-10-26) says the API builds a system prompt from the tool definitions, so every definition is input on every request. It calls the description "by far the most important factor in tool performance" and asks for at least 3 to 4 sentences per tool: what it does, when to use it and when not, and what each parameter means.

It also advises consolidating related operations into fewer tools, and prefixing tool names with the service when tools span several services.

Inference: that advice fits the corpus order of work. Fewer candidates first, then fuller descriptions for the pairs that remain.
