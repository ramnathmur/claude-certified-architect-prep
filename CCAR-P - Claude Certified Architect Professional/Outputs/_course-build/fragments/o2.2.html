Suppose a bank's assistant handles 40,000 conversations a month, 14 turns each on average, which is 560,000 turns in all. The team wants every reply formal, and wants any refund above $500 sent to a person. They write both rules into the first message of each conversation. On a long call, a customer asks for $620 at turn 12 and the assistant, by then casual, approves it.

The rules were written down and they were still not in force. Where a rule lives decides whether the model treats it as an instruction on turn 12.

Put persistent rules in the system prompt, and scope each guardrail to its layer§2.2

The system prompt is the instruction block set before the user speaks. It is the only location with durable authority across the whole conversation, so tone, persona and response-format rules for the whole conversation belong there.

The other places fail, each in its own way. A rule stated in the first user message is not durable: it loses authority once the conversation moves past that turn. A rule "set" through an environment variable has no effect at all, because environment variables configure infrastructure and never reach the model.

Guardrails follow the same placement. A guardrail is a refusal boundary or an escalation trigger, and it belongs in the system prompt. It is a design decision made when the system prompt is written, and a monitoring alert added later does not replace it.

Scope matters as well. Suppose a guardrail must react differently depending on which tool or sub-agent is active. Put it in a per-tool or per-agent system prompt, at the layer where the risk occurs, and leave the top level with what applies everywhere. One blanket top-level rule either over-restricts the contexts that do not need it or under-restricts the one that does.

The guide's objective also names templates, meaning prompts with fixed text and slots for variable content. The corpus rules for this section are about where rules live and how guardrails are scoped, and the corpus has no separate rule for templates. Modular prompts are covered in O2.5.

Both belong in the system prompt. The first message loses authority as the conversation moves on, and an environment variable never reaches the model. For the stricter agent, scope the guardrail to that agent's own layer with a per-agent prompt, instead of tightening one global rule.
